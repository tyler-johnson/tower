# plan

The goal is whatever this conversation has been building toward. Turn it into flights tower stores. Planning files flights and links; it never claims and never edits code. Once the flights are filed, this conversation is disposable — tower is the durable half of the plan.

Understand before cutting. Read enough of the repository to place real seams; a flight is one claimable stretch of work, not a heading.

Check the shelf first: `atc procedures`. When an installed procedure matches the shape of the work, file under it — `atc file <procedure> "<subject>"` — rather than hand-rolling its parts.

Choose the shape. Work one sitting finishes is one flight: `atc file "<subject>" -m "<body>"`. Work with distinct parts is a parent split with `atc decompose <flight> "<part>" "<part>"`, or separate filings joined with `atc link <a> <b>` for each real ordering. Link only where the order is load-bearing — unlinked flights can fly together, and that is the point of leaving them unlinked.

Write each brief for a cold reader: the files it touches, the prior art by path, the verify command, and what done looks like. The flight's facts only.

Decisions settle here. The person they belong to is in this conversation, so ask now, in this run — every choice the briefs depend on. Only a question that genuinely cannot settle here — it needs someone absent, or information nobody present has — becomes a flight of its own, crewed to a person — `atc assign <flight> me` — and linked ahead of its dependents. Never a silent guess, and never a hold parked for later when its owner is sitting right here.

End with a person. The last flight of any plan is theirs — review, verify, decide.

Sanity pass, then report: `atc board` to see the whole shape, then report the flights filed with their numbers and edges, and stop.
